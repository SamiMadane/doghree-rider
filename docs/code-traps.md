# Code traps

Non-obvious pitfalls in this codebase. Add an entry when one costs time.

| Trap | Where | Why it bites | Safe pattern |
|---|---|---|---|
| `flutter run` / `flutter test` regenerate plugin registrants | macos/Flutter/GeneratedPluginRegistrant.swift, windows/flutter/generated_plugin_registrant.cc, windows/flutter/generated_plugins.cmake | They show up as modified after any Flutter run and can slip into a batch commit | Never stage them in a batch. `git restore` them before merging (D-01) |
| Logout ordering: no server call runs during logout | lib/features/auth/domain/repositories/auth_repository.dart `clearSharedData` | Since D-03 logout sends no `update-fcm-token`, because the server requires `fcm_token` and the old call always failed. The device is released through `deleteToken` instead. `clearSharedData` clears the token and header first, then runs the FCM cleanup. The rider token goes only in the Bearer header, and `postData` takes the headers when it is called, so a server call added after the clear goes out without auth (401) | If a logout server call is ever reintroduced, start it before the token and header are cleared and use `handleError: false`. Keep the FCM cleanup bounded (5 s) and keep the pending flag, so an offline logout is retried (D-02, D-03) |
| `updateToken` is gated by the notification setting | auth_repository.dart `updateToken`, `setNotificationActive` | `updateToken` returns early while the notification setting is off. A toggle-on that called it before saving `true` would register nothing | `setNotificationActive` saves the setting first, then calls `updateToken` (D-03) |
| `ProfileModel.fromJson` throws on a missing list | lib/features/profile/domain/models/profile_model.dart (`identity_image_full_url`) | `json['identity_image_full_url'].cast<String>()` throws when the field is null or missing, so a 200 response can still fail to parse | Callers must catch parse errors. `ProfileRepository.getProfileInfo` maps a parse error to `SessionStatus.unverified` (D-01). Tests must include the field |
| `Get.isBottomSheetOpen` misses most sheets | GetX 4.7.3 `route_observer.dart` (`route is GetModalBottomSheetRoute`); `showCustomBottomSheet` uses `showModalBottomSheet` | Only sheets opened with `Get.bottomSheet` count as open. A `ConfirmationBottomSheet` from `showCustomBottomSheet` is never seen, so `if (Get.isBottomSheetOpen) Get.back()` does nothing and a later `Get.back()` pops the screen under it | Close a `showCustomBottomSheet` sheet from its own tap, synchronously, with `Navigator.of(Get.context!).pop()` (see `acceptFromCard`) (D-04) |
| `Get.back()` closes a snackbar first | GetX 4.7.3 `extension_navigation.dart` `back()` | While a GetX snackbar is open, `Get.back()` closes the snackbar and returns without popping the route | Pop routes with `Navigator`, or show the toast only after navigation (D-04) |
| Never `.cast`, `.forEach` or forced reads on response data | repositories and models (`lib/helper/json_helper.dart`) | A 200 with a Map or String body, a null list field or one bad item throws inside the repository or `fromJson`, and the caller's loader hangs. The profile parse error also looks like an expired session (D-05, rows 52, 53) | Use `JsonHelper.mapList` for lists (null means failure, `[]` means empty), `stringList`, `asInt`, `asDouble` and `asString` for fields. `mapList` skips bad items, so a skipped running order is hidden from the rider |
| History paging belongs to the controller | `OrderController.loadNextHistoryPage` | Computing the page count from the filtered list (orders without items are dropped on the phone) loads too few or too many pages. Page 1 bumps a generation, so a late page is ignored | Use `hasMoreHistory` (server `total_size`), keep one request in flight, and let only Retry continue after a failed page (D-05) |
| `getModule` is called from `build` | `SplashController.getModule` | A null or unknown `module_type` used to throw and show a red screen. It now returns an empty `Module()` with null flags | Read its flags with `?? false`, never with `!` (D-05) |
| One mapping for push taps | `lib/helper/notification_router.dart` (`NotificationRouter`) | Before D-07 the local tap, onMessageOpenedApp and splash each had their own type-to-route map, and they drifted (`withdraw` was missing at cold start). Push ids arrive as strings, `''` (the withdraw push) or not at all | Change targets only in `NotificationRouter.targetFor`. Read push ids with `NotificationRouter.validId`, never `int.parse`. A request push opens the Requests tab, never the pushed order (R2). Tabs use `offAllNamed`, so a second Dashboard (and a second `onMessage` listener) is never stacked (D-07) |
| A poll must not blank or close Order Details | `OrderController.getOrderWithId` | The order is cleared only when another id loads. A failed poll keeps it. Only a real 404 or 204 closes the screen, and the screen closes itself (`_closeGoneOrder`), never the controller | Keep navigation out of the controller. Callers act on the returned `OrderFetch` (D-04) |
