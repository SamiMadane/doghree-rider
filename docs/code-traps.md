# Code traps

Non-obvious pitfalls in this codebase. Add an entry when one costs time.

| Trap | Where | Why it bites | Safe pattern |
|---|---|---|---|
| `flutter run` / `flutter test` regenerate plugin registrants | macos/Flutter/GeneratedPluginRegistrant.swift, windows/flutter/generated_plugin_registrant.cc, windows/flutter/generated_plugins.cmake | They show up as modified after any Flutter run and can slip into a batch commit | Never stage them in a batch. `git restore` them before merging (D-01) |
| Logout ordering: no server call runs during logout | lib/features/auth/domain/repositories/auth_repository.dart `clearSharedData` | Since D-03 logout sends no `update-fcm-token`, because the server requires `fcm_token` and the old call always failed. The device is released through `deleteToken` instead. `clearSharedData` clears the token and header first, then runs the FCM cleanup. The rider token goes only in the Bearer header, and `postData` takes the headers when it is called, so a server call added after the clear goes out without auth (401) | If a logout server call is ever reintroduced, start it before the token and header are cleared and use `handleError: false`. Keep the FCM cleanup bounded (5 s) and keep the pending flag, so an offline logout is retried (D-02, D-03) |
| `updateToken` is gated by the notification setting | auth_repository.dart `updateToken`, `setNotificationActive` | `updateToken` returns early while the notification setting is off. A toggle-on that called it before saving `true` would register nothing | `setNotificationActive` saves the setting first, then calls `updateToken` (D-03) |
| `ProfileModel.fromJson` throws on a missing list | lib/features/profile/domain/models/profile_model.dart (`identity_image_full_url`) | `json['identity_image_full_url'].cast<String>()` throws when the field is null or missing, so a 200 response can still fail to parse | Callers must catch parse errors. `ProfileRepository.getProfileInfo` maps a parse error to `SessionStatus.unverified` (D-01). Tests must include the field |
| `Get.isBottomSheetOpen` misses most sheets | GetX 4.7.3 `route_observer.dart` (`route is GetModalBottomSheetRoute`); `showCustomBottomSheet` uses `showModalBottomSheet` | Only sheets opened with `Get.bottomSheet` count as open. A `ConfirmationBottomSheet` from `showCustomBottomSheet` is never seen, so `if (Get.isBottomSheetOpen) Get.back()` does nothing and a later `Get.back()` pops the screen under it | Close a `showCustomBottomSheet` sheet from its own tap, synchronously, with `Navigator.of(Get.context!).pop()` (see `acceptFromCard`) (D-04) |
| `Get.back()` closes a snackbar first | GetX 4.7.3 `extension_navigation.dart` `back()` | While a GetX snackbar is open, `Get.back()` closes the snackbar and returns without popping the route | Pop routes with `Navigator`, or show the toast only after navigation (D-04) |
| Never `.cast`, `.forEach` or forced reads on response data | repositories and models (`lib/helper/json_helper.dart`) | A 200 with a Map or String body, a null list field or one bad item throws inside the repository or `fromJson`, and the caller's loader hangs. The profile parse error also looks like an expired session (D-05, rows 52, 53) | Use `JsonHelper.mapList` for lists (null means failure, `[]` means empty), `stringList`, `asInt`, `asDouble` and `asString` for fields. `mapList` skips bad items, so a skipped running order is hidden from the rider |
| History paging belongs to the controller | `OrderController.loadNextHistoryPage` | Computing the page count from the filtered list (orders without items are dropped on the phone) loads too few or too many pages. Page 1 bumps a generation, so a late page is ignored | Use `hasMoreHistory` (server `total_size`), keep one request in flight, and let only Retry continue after a failed page (D-05) |
| `getModule` is called from `build` | `SplashController.getModule` | A null or unknown `module_type` used to throw and show a red screen. It now returns an empty `Module()` with null flags | Read its flags with `?? false`, never with `!` (D-05) |
| One mapping for push taps | `lib/helper/notification_router.dart` (`NotificationRouter`) | Before D-07 the local tap, onMessageOpenedApp and splash each had their own type-to-route map, and they drifted (`withdraw` was missing at cold start). Push ids arrive as strings, `''` (the withdraw push) or not at all | Change targets only in `NotificationRouter.targetFor`. Read push ids with `NotificationRouter.validId`, never `int.parse`. A request push opens the Requests tab, never the pushed order (R2). Tabs use `offAllNamed`, so a second Dashboard (and a second `onMessage` listener) is never stacked (D-07) |
| Binary responses are not text | `ApiClient.handleResponse`, `http.Response.body` | `http.Response.body` decodes with the charset in the header, or latin1 when there is none. A PDF sent with `charset=utf-8` throws a FormatException inside `handleResponse`, which becomes statusCode 0, and without a charset the bytes only survive by accident. `bodyString.codeUnits` is never a safe way to get bytes back | Download files with `ApiClient.getBytes`, which keeps `bodyBytes` untouched. Check the file signature (`%PDF-`) before writing. Log the length only (D-08, row 41) |
| Withdraw errors share one status | `WalletRepository.requestWithdraw`, `classifyWithdraw` | A 403 from `wallet/withdraw` is either a field-name validation code or a domain code, and the localized message text changes (`:date`, `:amount`). Branching on the text, or on the status alone, mixes "fix the form" with "the wallet state changed" | Decide from the status and the first recognized `errors[].code` in list order (`errorCodes`, `classifyWithdraw`). Show the server text, never parse it. Let `can_request_withdraw` and `withdraw_block` from `GET wallet` drive the button (D-08) |
| Wallet refreshes are silent | `WalletController.getWallet`, `getWithdrawals` | They run after deliveries, pushes, Home and every wallet action. With `handleError: true` an offline rider got several toasts for one tap, and a reset on failure would show a zero balance | Keep them `handleError: false` plus `checkSession`, and keep the last known values on any failure (D-08, row 43) |
| A poll must not blank or close Order Details | `OrderController.getOrderWithId` | The order is cleared only when another id loads. A failed poll keeps it. Only a real 404 or 204 closes the screen, and the screen closes itself (`_closeGoneOrder`), never the controller | Keep navigation out of the controller. Callers act on the returned `OrderFetch` (D-04) |
| Delivery photos ride on the status request | `OrderController.updateOrderStatus`, update-order-status | `order_proof[]` is sent with `delivered` itself and there is no photo endpoint. A photo problem (a file gone from the cache, an oversize body, a timeout) used to fail or hide the delivery, and a blind retry after a lost response could look like a double delivery | Check photos before the send (`ImageUploadRules`), never resend `delivered` by itself after a failure with photos: ask the server with one `GET order` first (`classifyProofFailure`, D-09). The only resend is the rider's Yes to deliver without photos after a 413 (or the dropped-body 403) with the order still `picked_up` |
| `Dimensions` values are frozen at first use | lib/util/dimensions.dart (`static double h76 = 76.h;`) | Each field is a lazily initialised static: it is computed once, from the ScreenUtil scale of that moment, and never again. In tests every later screen size reuses the first size's values | Test one screen size per test file (own isolate), as the D-10 `bottom_nav_overflow_<size>_test` files do. Never put image pixels or quality in `Dimensions` (`ImageUploadRules.pickMaxDimension`) (D-10) |
| Upload types come from the bytes | `ApiClient.postMultipartData`, `lib/helper/upload_format.dart` | The server stores a file by the type it detects from the content. Labelling by extension sent iPhone HEIC as `image/jpeg` | Use `UploadFormats.sniff` for the part type and filename. Refuse anything but jpeg, png and webp when the image is picked, with the one limit `ImageUploadRules.maxImageBytes` (D-09) |
| A 200 can carry an HTML page | `ApiClient.handleResponse`, every `fromJson(response.body)` | A captive Wi-Fi portal or a proxy error page answers 200 with HTML. The body fails to decode and arrives as a String, so `fromJson(body)` throws a TypeError and `body['message']` throws on a String index. Before D-12 this left loaders on in chat, forgot password and cancel reasons | Check `response.body is Map<String, dynamic>` (or use `JsonHelper`) before parsing a 200, and treat anything else as a failure (D-12) |
| R8 is already on in release | `android/app/build.gradle.kts`, Flutter Gradle plugin | The file sets no `isMinifyEnabled`, which looks like R8 is off, but the Flutter plugin turns on R8 and resource shrinking for release by default (`mapping.txt` is produced) | Do not add or change minify or keep rules without a release test on a real device (D-12) |
| Firebase may not exist | `FirebaseState.ready` (`lib/helper/firebase_state.dart`) | `main()` keeps going when `Firebase.initializeApp` fails. Any `FirebaseMessaging.instance` or `FirebaseAuth.instance` call then throws `[core/no-app]` and can break login or logout | Check `FirebaseState.ready` (or go through `PushClient`) before any Firebase call (D-12) |
| A JSON string and raw HTML look the same | `ApiClient.handleResponse`, `Response.body` | A body that decodes keeps its decoded value; one that does not keeps the raw text. So the page `"<p>..</p>"` and a captive Wi-Fi login page both arrive as a String in `body` | When a String is the expected shape, decode `response.bodyString` and check the result is a String (`HtmlRepository.readHtmlText`) (D-13) |
| No `update()` from a load called in `initState` | controllers whose loads start in a screen's `initState` (`ChatController`, `HtmlController`, `NotificationController`) | Calling `update()` synchronously there can mark other GetBuilders dirty during a build | Reset state silently before the first `await`; let the first build read it. Retry entry points (`retryConversationList`, `retryMessages`, `retry`, `retryNotificationList`) may call `update()` because they run from a tap (D-13) |
